# Identical-point normal-distance diagnosis

This follows [scene 50 appearance and scene 42 normal isolation](mandel-appearance-and-normal-isolation.md).
The camera-free differential test now reproduces scene 42's error. No production
renderer, sampling default, production normal estimator, export format or NAADF
code was changed. The diagnostic-only analytic derivative now passes both the
identical-point and fresh-ray scene-42 gates. Nothing was committed or pushed.

## Test construction

1. Select 1,024 evenly distributed actual FPT hit pixels from the existing
   200x112 scene-42 structural dump. These are fixed sample points, not new rays.
2. Ask the production normal function for its normal and finite-difference
   offset. Build its six axis-aligned sample positions in float64.
3. Evaluate native Mandelbulber at those positions, then at the same positions
   rounded to float32. Convert FPT world coordinates to native XYZ exactly once.
4. Evaluate Metal at precisely those rounded positions. Form normals from each
   set of six distance samples, separately measuring input rounding and evaluator
   disagreement.

The native adapter links existing objects from the actual native build and calls
`CalculateDistance` with normal-calculation mode enabled. It does not substitute
a handwritten formula. Existing objects keep their original compiler flags;
this is native double arithmetic, not an arbitrary-precision oracle. The wrapper
is compiled without fast-math. Native source and objects remain untouched.

The Metal probe is a separate diagnostic entry point. Its normal at the original
positions agrees with the production dump to median 0 degrees and P95 0.00000121
degrees. Reconstructing normals from its explicit six samples agrees with its
normal helper to median 0.00000121 degrees. This validates the sampling interface
for the selected points; it is not a universal compiler-equivalence claim.

## Results

| Comparison | Median | P95 |
| --- | ---: | ---: |
| Native normal change from rounding sample positions | 0.0515 degrees | 0.5705 degrees |
| Metal vs native normals at identical rounded positions | 7.5079 degrees | 32.8428 degrees |
| Metal/native distance relative error, 6,144 samples | 7.9988% | 32.2759% |

No native or Metal gradients collapse to zero. The same adapter on scene 30,
using 256 hit positions and 1,536 distances, gives median normal disagreement
0.1545 degrees and median relative distance error 0.2118%. Its P95 normal
disagreement is 1.3561 degrees.

This localizes a real residual to scene 42's distance evaluator. Camera framing,
hit selection and rounding of the outer normal stencil cannot account for the
identical-point disagreement. It does not yet isolate every error inside the
orbit and delta-derivative arithmetic.

## Derivative-step experiments

Formula 85 uses numerical radial derivatives. Production Metal uses a wider
float32-compatible inner delta than native CPU's detail-dependent double delta.
This is distinct from the outer six-sample normal offset.

As a diagnostic, the native evaluator was asked to use Metal's wider delta while
retaining its own orbit arithmetic. Metal/native median normal disagreement
only changes from 7.5079 to 7.3782 degrees; P95 worsens to 61.1313 degrees.
Matching the nominal delta alone therefore does not solve the problem. Remaining
differences include floating-point orbit evaluation and inner coordinate
rounding, which this test does not independently separate.

The Metal-only diagnostic sweep uses the same fixed hit positions and native
reference. It does not change the production library or camera rays.

| Inner delta multiplier | Median normal error | P95 normal error | Median distance relative error |
| --- | ---: | ---: | ---: |
| 0.5 | 12.7351 degrees | 59.0731 degrees | 13.8530% |
| 1, existing production | 7.5079 degrees | 32.8428 degrees | 7.9988% |
| 2 | 5.9447 degrees | 34.0958 degrees | 5.7228% |
| 4 | 6.9102 degrees | 50.9975 degrees | 6.4328% |

No multiplier was promoted. The best median still has a large residual and a
worse high-error tail. These are field/normal tests only, not fresh image-parity
gates or performance measurements.

## Adapter validation and excluded runs

The first adapter omitted parts of native startup initialization. An independent
scene-30 control caught the problem: it reported a spurious 116-degree median
normal discrepancy. Initializing locale state and parameter-container names as
the application does restored the expected sub-degree control result. The final
adapter saves fully resolved native settings next to its output for inspection.

Use only reports generated by `mandel-native-distance-probe-initialized` for
conclusions. Earlier `mandel-stencil30-control`, `mandel-stencil42-smoke`,
`mandel-stencil42-full` and `mandel-stencil42-delta` are exploratory evidence,
not accepted gates. Scene 42 happened to retain the same numbers after the fix;
it was rerun rather than assumed valid. The attempted scene-14 control was
explicitly rejected because the adapter does not support its scene configuration.
It is not a scene-14 rendering failure.

## Orbit error decomposition

`run_mandel_orbit_probe.py` compares the actual native
`Compute<calcModeDeltaDE1>` orbit with the generated Metal orbit at 6,144 base
points and 18,432 positive-axis perturbations. Native source and object files
remain unchanged. Native iteration bookkeeping is normalized: when its loop
exhausts, `iters` includes one extra count, distinguished by `maxiter`.

| Measurement | Result |
| --- | ---: |
| Matching base iteration counts | 6,117 / 6,144 |
| Median base radius relative error | 0.2248% |
| Median shifted radius relative error | 0.2217% |
| Median radial-difference relative error, matching base counts | 16.8863% |
| Native shifted queries ending before Metal's forced budget | 220 / 18,432 |
| Median native radius change from rounding shifted inputs | 0.00182% |

Subtracting nearby radii magnifies small orbit discrepancies. Iteration
divergence exists but is uncommon in this sample; changing the bailout alone
would not explain most of the error. These measurements support a derivative
precision hypothesis, not a claim that float32 orbit evaluation is exact.

```sh
python3 scripts/run_mandel_orbit_probe.py \
  --stencil reports/mandel-stencil42-gate \
  --diagnostic reports/mandel-aux-directional-normal42/42 \
  --metal-probe target/release/examples/mandel_normal_probe \
  --native-probe reports/mandel-native-orbit-probe/native-distance-probe \
  --output reports/NEW-orbit42
```

The accepted evidence is `reports/mandel-orbit42/summary.json`. The new native
adapter supports `orbit85` in addition to its two distance modes. The orbit
probe uses explicit forced budgets; it does not alter production bailout rules.

## Analytic derivative candidate

`examples/precision/analytic85.rs` propagates a 3x3 Jacobian through the local
scaling and inversion map. It computes the radial derivative as `J^T z / |z|`,
without subtracting nearby orbit radii. Orbit positions still use the original
runtime-translated formula. Appearance/color orbits are not modified.

This is restricted to standalone formula 85, zero initial W, no global box or
sphere folding, no post-iteration C addition and no sine branch. Unsupported
source shapes fail closed. Periodic rounding has derivative one away from its
discontinuities; the candidate does not claim differentiability at a discontinuity
or a branch boundary. No upstream formula body is vendored into the helper.

| Identical-point comparison | Production field | Analytic diagnostic |
| --- | ---: | ---: |
| Median normal error | 7.5079 degrees | **0.4935 degrees** |
| P95 normal error | 32.8428 degrees | **2.3851 degrees** |
| Median distance relative error | 7.9988% | **0.5380%** |
| Collapsed gradients | 0 | 0 |

The one-degree median gate passes. Report:
`reports/mandel-stencil42-analytic-v2/summary.json`.
The earlier `mandel-stencil42-analytic` directory is an excluded, failed source
guard attempt: the first bounded replacement also saw a material orbit. The
corrected helper limits replacement to the distance-orbit/field section; a
regression test ensures the material section remains untouched.

```sh
FPT_NORMAL_PROBE_ANALYTIC85=1 python3 scripts/run_mandel_stencil_probe.py \
  --diagnostic reports/mandel-aux-directional-normal42/42 \
  --metal-probe target/release/examples/mandel_normal_probe \
  --native-probe reports/mandel-native-orbit-probe/native-distance-probe \
  --output reports/NEW-analytic42 --count 1024 --max-normal-median 1
```

### Fresh-ray gate

The separate `mandel_derivative_render` example dynamically compiles the same
diagnostic kernels at 200x112, one sample, fixed authored camera. Its baseline
structural dump is **byte-exact** with the original production-compiled
diagnostic. This validates the baseline for this test; it is not a general
compiler-equivalence guarantee.

| Fresh-ray measurement vs native | Baseline | Analytic diagnostic |
| --- | ---: | ---: |
| Median normal error | 9.2120 degrees | **0.6735 degrees** |
| P95 normal error | 98.2572 degrees | **6.8603 degrees** |
| Median relative depth error | 0.09226% | **0.01498%** |
| P95 relative depth error | 1.26613% | **0.08649%** |
| Native-visible misses | 0 | **0** |
| Extra hits vs native | 3 | **1** |

Two pixels change from hit to miss relative to the old FPT output. Both are
native misses, so these remove false hits rather than losing native-visible
geometry. The gate checks baseline byte identity, sub-degree median normal
error, improved normal tail/depth median, and no additional native-visible
misses. This is an intentional correctness experiment, not byte-exact candidate
output or a performance optimization claim.

![Scene 42 normal comparison](../reports/mandel-analytic42-render/comparison/comparison.png)

The local comparison is an ignored diagnostic artifact, not a distributable
README asset. Fresh render inputs, output records and hashes are in
`reports/mandel-analytic42-render/{baseline,analytic}`. Run the example twice,
with the environment switch absent/present, keeping every render argument
identical:

```sh

  reports/mandel-aux-directional-controls/42/no-shadows/control.fract \

  --sdf-bounce-cap 1 --sdf-accumulation chunked --sdf-chunk-samples 1 \
  --mode normal --out reports/NEW-analytic-render
```

`summarize_mandel_derivative_render.py` compares these records to the stored
native/production control and generates the normal contact sheet. This is not
an authored beauty/path-tracing test; diagnostic GPU intervals are not a
production benchmark.

Current verification: 227 project Rust tests, three diagnostic source-guard
tests and 52 Python tests pass; whitespace checks pass. The gated fresh-ray
summary is `reports/mandel-analytic42-render/gated-comparison/summary.json`.
The production executable retains the SHA-256 recorded above. No production
